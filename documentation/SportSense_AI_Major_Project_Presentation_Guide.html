SportSense AI — Biomechanical Movement & Sports Talent Assessment

An Accessible Computer Vision, Biomechanical Kinematics & Multi-Model Machine Learning Platform

2-Minute Elevator Pitch (For College Presentation Opening):
"Respected evaluators, modern sports academies rely on expensive force plates and 3D motion-capture laboratories costing lakhs of rupees, making scientific talent assessment inaccessible to 95% of grassroots and school athletes. SportSense AI solves this problem by using standard smartphone and webcam video to capture 33 human anatomical landmarks in real-time with MediaPipe and OpenCV. By extracting kinematic physics parameters across five standardized assessments, classifying athletic suitability across six sports with machine learning, and delivering natural-language coaching via an LLM, our system provides objective, democratized athletic talent identification without any specialized hardware."
1. Problem Statement
  • High Barrier to Entry: Commercial biomechanics rigs (Vicon, Qualisys, Bertec force plates) cost over $20,000.
  • Subjective Scouting: Physical education teachers rely on manual stopwatches and eyeball observations, introducing human bias.
  • Unidentified Talent: Grassroots and school athletes lack access to scientific sport recommendations matching their physical strengths.
2. Proposed Solution
  • Commodity Hardware: Works on standard 30 FPS webcams and smartphone cameras with zero external sensors.
  • Deterministic Kinematics: Measures true physics metrics (flight time, joint flexion angles, balance sway, agility transition velocity).
  • Multi-Model AI Guidance: Combines scikit-learn classification for multi-sport fit scoring with local Ollama Qwen2.5:3b for athlete coaching.

Main Objectives:

Democratize athletic screening using commodity webcams; measure objective physical kinematics in <3s; classify multi-sport fit across 6 sports; synthesize personalized AI coaching drills.

School athletes (development tracking); Physical Education teachers & coaches (squad screening); Sports scouts (metric-driven identification); Parents (early sport discovery).

2. System Architecture & End-to-End Technical Working

Complete Processing Pipeline from Video Ingestion to Machine Learning & Natural Language Coaching

Technical Components (Explained in Plain English)

Component Technology Used Exact Role in the Application
Frontend UI React 18, Vite, TanStack Router, Tailwind Responsive user interface, manages camera stream via getUserMedia, draws live skeleton canvas overlay, and presents dynamic Radar charts.
Backend API FastAPI, Uvicorn, Python 3.11+ Asynchronous REST service. Accepts multipart video uploads, handles temporary streaming buffers, orchestrates vision pipelines, and exposes modular API endpoints.
Computer Vision OpenCV (cv2) & MediaPipe Pose Extracts 33 anatomical landmarks (x, y, z, visibility) per frame at 30 FPS. Calculates joint angles and applies optical flow fallback if keypoints are obscured.
Database & Auth Supabase Cloud (PostgreSQL 15) Stores profiles, runs, attempts, and results across 8 relational tables. Implements Row-Level Security (RLS) and handles Google OAuth and Email authentication.
Machine Learning Scikit-Learn (LogisticRegression, GroupKFold) Evaluated 6 classifiers (LR, Random Forest, SVM, KNN, Naive Bayes, XGBoost). Best model maps 5 kinematic traits to multi-sport probability distributions.
AI Coaching LLM Ollama (Qwen2.5:3b) + Biomechanics Fallback Generates structured coaching summaries, athletic strengths, and specific training drills. Automatically falls back to calibrated biomechanical rules if offline.
Deployment Vercel (Frontend) & Render (Backend) Frontend served at global edge with reverse proxy rewrite (/api/*). Backend containerized on Linux cloud with OpenCV libraries and CORS integration.
CRITICAL VIVA DISTINCTION — CV vs. ML vs. LLM:
• Computer Vision (OpenCV + MediaPipe): Observes & Measures. Detects physical keypoints and derives raw kinematic metrics (e.g., flight time = 0.58s, knee angle = 88°).
• Machine Learning (Scikit-Learn Classifier): Pattern Recognizes & Classifies. Maps the 5 normalized physical traits (Explosive Power, Strength, Balance, Agility, Coordination) to the top matching sport among Basketball, Volleyball, Football, Tennis, Badminton, and Cricket.
• Large Language Model (Ollama / Qwen2.5): Explains & Communicates. Synthesizes measurements into plain-English coaching advice. The LLM never directly measures movement!
Vertical Jump End-to-End Calculation Example:

1. Athlete uploads jump video ➔ 2. OpenCV reads frames at 30 FPS ➔ 3. MediaPipe tracks Hips (#23, #24) Center of Mass ➔ 4. Flight time detected: t = 0.58s between takeoff and landing ➔ 5. Physics formula: h = 1/8 * 9.80665 * (0.58)² = 41.2 cm ➔ 6. Explosive Power score: 88/100 ➔ 7. ML Classifier predicts Top Sport: Basketball (88%) ➔ 8. Qwen LLM outputs personalized coaching drill.

3. Team Presentation Division & Viva Responsibilities

Four Balanced, Technically Distinct Modules Designed for Clear Project Defense

MEMBER 1: Frontend Engineering, UI/UX, Camera Capture & Authentication

Technologies: React 18, TypeScript, TanStack Router, Tailwind CSS, Lucide Icons, MediaDevices Web API, Sonner.

"I was responsible for the client-side user experience, authentication workflows, and real-time camera interfaces. Our frontend is structured using TanStack Router for type-safe routing. We implemented Google OAuth with auto-profile sync and Email/Password authentication. When an athlete begins an assessment, our interface uses HTML5 MediaDevices to stream 30 FPS video, displays live positioning guides and countdown overlays, captures video buffers, and posts them to our backend while displaying interactive Radar charts and talent breakdown reports."
Q: Why choose TanStack Router over standard React Router?
A: TanStack Router provides 100% type-safe route parameters, automatic search-param validation, and built-in code-splitting without runtime navigation crashes.
Q: How does video recording work directly inside the browser?
A: We access the camera using navigator.mediaDevices.getUserMedia, render the stream onto a <video> element, and capture compressed video blobs using the MediaRecorder API before transmitting to the FastAPI server.
MEMBER 2: Backend Architecture, PostgreSQL Database & Cloud Deployment

Technologies: FastAPI, Python 3.11, Uvicorn, Supabase (PostgreSQL 15), Row-Level Security (RLS), Docker, Render, Vercel.

"I managed the backend infrastructure, database design, and cloud deployment pipelines. I built a modular asynchronous REST backend using FastAPI and Pydantic schemas. I designed our Supabase PostgreSQL schema spanning 8 relational tables—including profiles, assessments, attempts, and talent reports—protected by Row-Level Security policies. To deploy, I containerized the backend on Render Linux and configured Vercel edge reverse proxying to route /api/* requests seamlessly without CORS issues."
Q: Why choose FastAPI instead of traditional Flask or Django?
A: FastAPI is natively asynchronous (ASGI), allowing high-concurrency video uploads without thread blocking. It also provides automatic OpenAPI Swagger documentation and automatic Pydantic request validation.
Q: How is database security enforced between different athletes?
A: We use Supabase PostgreSQL Row-Level Security (RLS). Database policies check the JWT auth.uid(), ensuring athletes can only query and mutate their own assessment attempts and medical profiles.
MEMBER 3: Computer Vision, Pose Tracking & Biomechanical Feature Extraction

Technologies: OpenCV (cv2), MediaPipe Pose (33 Landmarks), NumPy, Trigonometric Kinematics, Moving Average Smoothing.

"My focus was the computer vision pipeline that transforms video frames into biomechanical metrics. We integrate MediaPipe Pose to track 33 3D anatomical keypoints at 30+ FPS. For each of the five assessments, I implemented specialized kinematic extraction: flight-time physics for Vertical Jump, trigonometric knee flexion angles for Squat depth, center-of-mass sway variance for Single-Leg Balance, elbow state machines for Push-Up counting, and lateral bounding threshold checks for Agility."
Q: Why use MediaPipe Pose instead of heavy models like YOLOv8-pose or OpenPose?
A: MediaPipe Pose is optimized for lightweight CPU execution, running at 30+ FPS in real-time with low latency, whereas OpenPose and YOLO require dedicated GPUs that are inaccessible for commodity deployments.
Q: How do you calculate jump height without knowing camera distance?
A: We use flight-time projectile physics: h = (1/8) * g * (t_flight)². By identifying the exact takeoff frame and landing frame, flight time is independent of camera distance, focal length, or pixel perspective.
MEMBER 4: Machine Learning Classification, Local LLM Integration & Talent Synthesis

Technologies: Scikit-Learn, Joblib, GroupKFold Validation, Ollama, Qwen2.5:3b LLM, Multi-Sport Scoring Engine.

"I was responsible for training our multi-sport classification models, integrating our local LLM coaching engine, and synthesizing the final Talent Report. I benchmarked six machine learning models using subject-independent 5-fold GroupKFold validation to prevent data leakage. Logistic Regression achieved the highest balanced F1-score of 53.12% across 6 sports. I integrated local Ollama running Qwen2.5:3b to stream personalized drills, with an automatic deterministic Olympic fallback engine if offline."
Q: Why did Logistic Regression beat complex models like Random Forest and XGBoost?
A: With five normalized continuous athletic traits, complex tree ensembles overfit on small sample sizes. Logistic Regression provided superior generalization, zero data leakage, and well-calibrated class probabilities.
Q: What happens if Ollama or the local LLM server is not running during a demo?
A: The system features an automated deterministic Olympic Biomechanics fallback engine that parses the measured kinematics and generates structured coaching observations with zero latency, guaranteeing 100% uptime.

Top Master Viva Questions & Grounded Technical Answers

Q: Why does the system calculate Vertical Jump from flight time rather than pixel displacement?
A: Pixel displacement is distorted by camera-to-athlete distance, lens focal length, and optical distortion. In contrast, gravitational acceleration (9.81 m/s²) is constant on Earth. By detecting flight duration t, height h = (1/8)*g*t² is mathematically exact regardless of zoom or distance.
Q: What is the exact role of OpenCV vs. MediaPipe?
A: OpenCV handles low-level computer vision: reading video containers, frame decoding, color-space conversions (BGR to RGB), and optical flow motion fallbacks. MediaPipe Pose runs the deep neural network that detects the 33 anatomical 3D coordinates from those image frames.
Q: What database architecture was chosen and why?
A: Supabase PostgreSQL was chosen over NoSQL because biomechanical sessions are deeply relational (Users → Profiles → Assessments → Runs → Attempts → Results). PostgreSQL enforces foreign key cascades, JSONB flexibility for raw keypoints, and Row-Level Security.
Q: Why did you benchmark 6 ML models instead of just using a Neural Network?
A: Tabular kinematic data with 5 continuous features does not justify deep neural networks, which easily overfit small clinical datasets. By benchmarking Logistic Regression, Random Forest, SVM, KNN, Naive Bayes, and XGBoost under 5-Fold GroupKFold, we empirically proved Logistic Regression provides the highest generalization F1-score (53.12%).
Q: Can the Large Language Model (Qwen2.5) hallucinate false measurements?
A: No. The LLM is strictly constrained via prompt engineering to receive already-calculated kinematics (jump height, angles, scores) as static input context. It only translates pre-computed numerical facts into natural-language coaching tips; it never computes numerical values itself.
